# Repository Working Agreement

Before making code changes:

1. Analyze the request.
2. Show the implementation plan.
3. List every file that will be created, modified, renamed, or deleted.
4. Explain architectural decisions and alternatives.
5. Wait for explicit approval before writing or modifying files.

## Default mode

- Use proposal mode first.
- Do not edit files without approval.

## Code changes

- Show diffs before applying them.
- Make changes in small batches.
- Do not refactor unrelated code.

## Safety

- Never delete files without approval.
- Never modify existing production applications unless explicitly requested.
- Never overwrite configuration files without approval.
- Ask clarifying questions before coding when requirements are ambiguous.
- For new projects, present the project structure and wait for approval before
  generating files.
